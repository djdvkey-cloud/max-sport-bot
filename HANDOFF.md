## 2. Что делает бот

Шесть клубов: Автомобилист (хоккей), Синара (мини-футбол), Урал, Реал Мадрид, Арсенал, Милан (футбол).
Вид спорта задан явно в конфигурации клуба (`sport`) и сводится к `football`/`hockey` через `SPORT_FAMILY`
(мини-футбол = футбол); нейросеть вид спорта не определяет.

1. **Утро (10:00 ЕКБ, раз в сутки)** — если клуб играет сегодня, анонс (формат прежний). Перед первым обычным
   анонсом дня — одна вводная фраза из набора по виду спорта дня: только футбол / только хоккей / оба вида
   (универсальный набор); без повторов подряд (последние индексы — в `sport_meta.json`).
2. **Афиша (понедельник, с 09:00 ЕКБ, раз в неделю)** — одно сообщение с матчами всех клубов на неделю
   пн–вс, отсортировано по времени; нет времени → «время уточняется»; матчей нет → ничего не отправляется.
   Источник — календари клубов из существующего списка страниц (`extract_urls`): детерминированный разбор,
   без нейросети. sports.ru: таблица сезона (время московское; «ночные» заглушки 00:00–03:59 = время не назначено),
   superliga.rfs.ru: «Будущие матчи» (время екатеринбургское; 00:00 = не назначено).
3. **Контроль изменений.** Афиша сохраняется в `schedule.json`. Утром в день матча бот заново получает
   данные (как прежде) и сверяет: время изменилось → одно сообщение «⚠️ изменилось время» вместо обычного
   анонса; матч перенесён на сегодня → одно сообщение «перенесён на сегодня»; матч из афиши на сегодня
   не найден, а календарь клуба показывает ту же игру на другую дату → «перенесён», с пометкой «отменён» → «отменён»;
   нет доказательств — молчим (не гадаем).
4. **Результат.** Первая проверка — через **2 часа** после начала матча (планировщик просыпается точно к этому
   моменту), далее каждые 20 минут. Разбор и оформление результата (победа/ничья/поражение, ОТ/буллиты)
   не менялись. Найденный результат **сохраняется** до подтверждённой отправки в MAX; отметка
   «опубликован» — только после успешной отправки; один матч публикуется один раз (`published_ids`).
5. **Защита от неверного счёта.** Перед публикацией результат сверяется: (а) источники из контекста
   (дата-привязанный иной счёт или «идёт» против «завершён» — конфликт); (б) календарь клуба (счёт и
   способ завершения; в таблице sports.ru счёт «хозяева:гости»); (в) если подтверждений меньше двух и задан
   `OPENAI_API_KEY` — независимая перепроверка через OpenAI (не чаще раза в час). Конфликт → в MAX ничего не
   уходит, проверка повторяется в обычном цикле; не устранён за 60 минут → одно личное уведомление.
   Недоступность одного источника публикацию не блокирует.
6. **Личные уведомления.** При нормальной работе бот молчит. Сбой, из-за которого работа не выполняется
   (источники недоступны, результат не найден к 4,5 ч, отправка в MAX не удалась, конфликт >60 мин,
   время начала неизвестно, внутренний сбой планировщика), — короткое личное сообщение один раз;
   повторы тихо; после восстановления — одно «✅». Без traceback. Тихое «✅ запущен» — один раз на версию.

## 2а. «Своя Трибуна» / «Трибун» — клубный слой (этап 2, 2026-10-03.3)

Публичный бренд: группа MAX **🏟️ Своя Трибуна**, бот **🤖 Трибун**. Технические имена SPORTBOT/MAX в коде остаются. Только MAX (maxapi), Telegram не используется.
Модули: `tribun.py` (личка, владелец, события группы), `tribun_catalog.py` (справочник), `tribun_io.py` (хранилище), `sources.py` (реестр источников),
`costs.py` (учёт API) и `tribun_hooks.py` (тонкие хуки в SPORTBOT). Выключатель: `TRIBUN_ENABLED=0` (хуки превращаются в прямой вызов).

### Что НЕ менялось (SPORTBOT)
- **Шесть клубов остаются в работе:** ХК «Автомобилист», МФК «Синара», ФК «Урал», «Реал Мадрид», «Арсенал» Лондон, «Милан» (`sport_bot.CLUBS`).
  Недельная афиша, утренние анонсы, контроль времени/переносов/отмен, поиск результатов, повторные проверки, cross-check, защита от неверного счёта, дедупликация,
  persistence, scheduler (один), owner alerts, прямые календари sports.ru / superliga.rfs.ru, Tavily → DeepSeek → OpenAI-резерв работают как раньше.
- **Автоматика не зависит от интересов участников.** Профили не читаются ни афишей, ни утром, ни результатами (проверяют тесты: афиша одинакова при «враждебных» профилях;
  в исходниках задач нет обращений к профилям). Удалить интерес = ничего не отключить. Каталог выбора ≠ список отслеживаемых клубов.
- Прямой парсинг календарей — детерминированный Python; ИИ его не заменяет и не является источником факта.

### MEMBER (личка участника)
Ровно три корневых пункта: **🏅 Виды спорта · 🏆 Чемпионаты · ❤️ Клубы** (+ технические «Сохранить / Дальше / Назад»); после сохранения — «✅ Интересы сохранены».
Удалены (не скрыты): «Что сегодня у меня?», личные уведомления/частота, спортсмены, тип контента, 5-шаговый мастер, «О Трибуне», любые персональные спортивные сообщения.
Вся спортивная повестка — только в группе; OWNER-уведомления в личку сохранены.
- **Виды спорта:** ⚽ Футбол, 🏒 Хоккей, 🥅 Футзал, 🏀 Баскетбол, ➕ Другое (мультивыбор).
- **Цепочка выбора:** вид спорта → чемпионаты выбранных видов → **клубы только выбранных чемпионатов** (объединение, клуб из двух турниров — одна кнопка). Модель SPORT → COMPETITION → SEASON → CLUBS
  в `tribun_catalog.py` (`COMPETITIONS`, `SEASONS`, `CURRENT_SEASON`); интерфейс клубов не знает — чтобы обновить сезон, достаточно заменить запись `SEASONS`.
- **Согласованный список чемпионатов:** хоккей — КХЛ, NHL; футбол — РПЛ / Премьер-лига, Первая лига, АПЛ, Ла Лига, Серия А, Лига чемпионов, Лига Европы, Лига конференций; футзал — Суперлига (для МФК «Синара»);
  баскетбол — минимально «Единая лига ВТБ» без источников (GAP); во всех — «➕ Другое». Кубок России убран; других чемпионатов нет.
- **Каталог выбора — снимок сезона 2026/27, проверен 2026-10-03** (SPORT → COMPETITION → SEASON → CLUBS → SOURCE → VERIFIED_AT в `tribun_catalog.py`: `SEASONS[comp] = {season, source_name, source_url, official, verified_at, clubs}`).
  Интерфейс интернет не опрашивает: проверенный снимок лежит в коде; новый сезон = обновить `SEASONS` и `CURRENT_SEASON`/`VERIFIED_AT`, callbacks не трогать. Состав не берётся по памяти модели.
  Источники и размеры: UEFA.com — Лига чемпионов/Лига Европы/Лига конференций (league phase, по 36; официально); LALIGA — таблица 2026/27 (20; официально); NHL.com (32; официально);
  КХЛ (22; khl.ru отдаёт 403 роботам → Спорт-Экспресс / T—J / Википедия); РПЛ (16), Первая лига (18; Урал сверен ещё и со страницей sports.ru «Россия. Первая лига»), АПЛ (20), Серия А (20) — Википедия 2026–27
  (сайты лиг не отдают список роботам: капча / только JS); Суперлига (12; superliga.rfs.ru показывает 2024/25 → состав по srrb.ru и спортивным СМИ); Единая лига ВТБ (12; vtb-league.com + Чемпионат, «Астана» по Чемпионату).
  Неофициальные источники помечены `official=False` — владелец может перепроверить их по сайтам лиг.
- **Исправленные ошибки старого каталога (2025/26):** Милан играет в Лиге Европы 2026/27 (в каталоге был только в Серии А); составы АПЛ/Ла Лиги/Серии А/РПЛ/Первой лиги/КХЛ/еврокубков заменены на 2026/27
  (вылетели/ушли: Бёрнли, Вест Хэм, Вулверхэмптон, Жирона, Мальорка, Овьедо, Кремонезе, Верона, Пиза, Сочи и Нижний Новгород из РПЛ, Витязь и др.; добавлены Ковентри, Халл, Ипсвич, Фрозиноне, Монца, Венеция, Депортиво, Расинг, Малага, Родина, Факел, Шанхайские Драконы и др.).
- **Шесть клубов SPORTBOT по турнирам 2026/27:** Автомобилист — КХЛ; Синара — Суперлига; Урал — Первая лига (не РПЛ); Реал Мадрид — Ла Лига + Лига чемпионов; Арсенал — АПЛ + Лига чемпионов; Милан — Серия А + Лига Европы.
- **Каталог выбора ≠ покрытие источниками.** Клуб есть в каталоге, но расписание Трибун/SPORTBOT получает только для шести клубов; остальные — GAP (допустимое состояние, так показывается владельцу в 🌐 Источники; «🏟 Покрытие» показывает дату снимка).
- **Снятый чемпионат/вид спорта:** связанные клубы неактивны в агрегате (выбор хранится, вернули чемпионат — клубы снова активны); клуб из двух выбранных чемпионатов остаётся активным, пока выбран хотя бы один.
- **Навигация:** клубы ⬅️ → чемпионаты ⬅️ → виды спорта ⬅️ → меню; «Дальше» есть у видов спорта и чемпионатов, на клубах — «✅ Сохранить» и «⬅️ Назад»; Назад ничего не очищает и не создаёт состояния;
  «Сохранить» подтверждает «✅ Интересы сохранены» и ведёт в меню, не трогая другие разделы. Известное название из справочника через «➕ Другое» становится обычным выбором (появится, когда выбран его чемпионат/вид спорта).
- **➕ Другое** (во всех трёх разделах) — это **запрос**, а не подписка: `tribun_requests.json`, запись `{category, raw_text, normalized_text, user_id, created_at, active}` (+ `id`).
  Нормализация простая, без fuzzy: регистр, ё/е, кавычки, дефисы, таблица точных псевдонимов («NBA» = «НБА», «Формула 1» = «Формула-1»). Известное название из каталога становится обычным выбором.
  Запрос не включает поддержку, парсер или публикации. Участник сам снимает свой запрос; чужой запрос тронуть нельзя.
- **Профиль настроен** = в каждом из трёх разделов есть выбор (вариант каталога или активный запрос). Каждый раздел правится отдельно. Убранный вид спорта скрывает связанные чемпионаты/клубы в агрегате,
  но данные не теряются (вернул спорт — всё на месте).
- **Совместимость:** профиль этапа 1 читается без разрушительной миграции — новые поля `championships`/`clubs` выводятся из старых `competitions`/`teams` только по точному совпадению с каталогом,
  старые поля остаются в файле нетронутыми. Данные переживают restart/deploy (атомарная запись, копии в `/data/backups`, повреждённый файл не перезаписывается).

### OWNER («🛠 Управление Трибуной»)
Роль — по стабильному MAX `user_id` (не по имени), проверяется на сервере дважды (`on_callback` и `route_admin`); у MEMBER админ-кнопки молча отклоняются. Меню владельца = три пользовательских раздела + управление:
👤 Участники · 👥 Интересы Трибуны · 📝 Запросы участников · 🌐 Источники · 💰 API / расходы · 📣 Публикации · 🗓 Автоматика · ⭐ Приоритеты · 📊 Состояние · 🔔 Уведомления · 📨 Приглашение.
- **Интересы Трибуны:** «Участников / Настроили профиль», «⚽ Футбол — 4», чемпионаты, клубы; считаются только `active_in_group`; убранный вид спорта скрывает связанные чемпионаты/клубы.
- **Запросы участников:** агрегаты значений «Другое» по трём категориям (без имён) и детальный экран: раздел, название, нормализованное, число активных запросивших, покрытие источниками, статус.
- **Карточка участника** (только просмотр): статус, профиль, 🏅/🏆/❤️ и ➕ запросы, даты. **Push владельцу** (в личку, не в группу): новый участник, впервые настроил профиль (карточка 🏅 Спорт / 🏆 Чемпионаты / ❤️ Клубы / ➕ Запросы, один раз),
  покинул, вернулся; мелкие правки, нажатия и открытия меню — не присылаются. Недоставленное досылается сверкой раз в 3 ч без дублей.

### Реестр источников («🌐 Источники», `sources.py`, `/data/tribun_sources.json`)
- Аудит: прямой HTTP (календари клубов — `calendar:<клуб>`), Tavily Search (`search:tavily`), OpenAI web_search (`search:openai`, резерв/cross-check). DeepSeek/OpenAI-модель — не источник факта.
  Иерархия типов: OFFICIAL > DIRECT > AGGREGATOR > MEDIA > SEARCH. Модель записи: source_id, name, domain, sport, competition, entity_ids, source_type, purpose (SCHEDULE/LIVE/RESULT/NEWS/CROSSCHECK), priority,
  health_status, last_success_at, last_failure_at, consecutive_failures, last_error_short, enabled. Секретов нет.
- **Health — только из реальных запросов** (сайты по таймеру не опрашиваются): 1 сбой подряд → 🟡, 3 → ❌, успех → ✅. **CONFIRMED_EMPTY** (страница получена, матчей нет) ≠ **SOURCE_FAILED** (не ответила / вёрстка изменилась) ≠ NOT_FOUND:
  сбой источника никогда не превращается в «матчей нет».
- **Coverage:** COVERED / FALLBACK_ONLY / GAP / FAILED по видам спорта, чемпионатам, клубам. Покрытие = то, что SPORTBOT реально отслеживает (шесть клубов). Найденные разрывы: **баскетбол и Единая лига ВТБ — GAP** (источников нет),
  любые «Другое» без совпадения с каталогом — GAP (gap detector без автопарсеров, платных API и публикаций). Экран: «✅ Футбол — OK / ✅ Хоккей — OK / ✅ Футзал — OK / 🟡 Баскетбол — источников пока нет», счётчики
  рабочих/проблемных/ещё не проверенных/непокрытых, кнопки 🏟 Покрытие, 🌍 Все источники, ⚠️ Проблемы, 🧩 Непокрытые интересы. Пока источник не проверялся, пишет «настроен, ещё не проверялся».
- **Алерты владельцу** (через прежние `raise_alert`/`clear_alert`, один раз + одно о восстановлении): только при повторных падениях (3 подряд) реально используемого источника, когда замены нет (поиск тоже недоступен).
  Прямой календарь работает при падении Tavily.

### Учёт API («💰 API / расходы», только OWNER; `costs.py` + `tribun_hooks.py`, `/data/tribun_usage.json`, `/data/tribun_pricing.json`)
- Хуки-декораторы на `collect_web_context_tavily`, `deepseek_completion`, `ask_openai_websearch`; каждый вызов: provider, operation, purpose (schedule_search / result_search / result_crosscheck / text_generation / fallback / admin_test),
  время, ok/failed, latency, cached/real, input/output tokens, credits/units (Tavily advanced = 2), estimated cost. Агрегаты по дням (Asia/Yekaterinburg) + последние 200 вызовов; переживают restart.
- **USAGE и ESTIMATED COST — раздельно.** Закэшированный ответ — cached, не real, стоимость 0; неуспешный вызов — отдельно, не тарифицируется. **Цены не выдуманы:** `DEFAULT_PRICING` содержит `None`; пока владелец не задал цену
  командой `/цена` (в личке, только OWNER), в экране «стоимость неизвестна». Конфиг цен: provider, model, input_price, output_price (за 1 млн токенов), credit_price, currency, effective_from, updated_at, source_note.
- Экран: сегодня / месяц, по провайдерам, cached, ошибки; кнопки 📅 Сегодня, 📆 Месяц, 🧠 AI, 🌐 API, 🎯 Назначение, ⚠️ Ошибки.
- **Экономия:** факты находит Python, а не LLM; один матч — один поиск; кэш одинаковых запросов (Tavily 180 с, DeepSeek/OpenAI 120 с); DeepSeek — основной, OpenAI — только резерв; личных рассылок нет.
- **Cost guards:** пороги вызовов за день/месяц (предупреждение владельцу один раз на день/месяц/провайдера), аномальная частота вызовов (10 мин, по назначению), пауза после 3 неудач одного и того же запроса (защита от бесконечного retry),
  защита от параллельного дубля. Останавливается только проблемный процесс (`CostGuardBlocked`), остальные работают; сбой самой защиты не блокирует работу (fail-open).
- Хуки не меняют логику SPORTBOT: без `configure` это прямой вызов; все прежние тесты проходят и с включёнными хуками.

- **Запуск.** `main()` настраивает хуки, запускает слушатель MAX (`Dispatcher.start_polling`, перезапуск через 30 с при сбое) и сверку состава группы параллельно с прежним планировщиком (он один); сбой слоя клуба не останавливает анонсы.
- **Тесты** (`tests/`, всего **335**): `test_sport_v4` 79 (прежние 78 + проверка назначения cross-check), `test_tribun` 37, `test_tribun_member` 12 (пункты MEMBER + защита чужих запросов), `test_tribun_catalog` 8 (снимок 2026/27: сезон, источники, размеры, легаси-клубы, устаревшие составы, union, каталог ≠ покрытие), `test_tribun_flow` 21 (чемпионаты, клубы по чемпионатам, union, снятие чемпионата, сезонность, Назад/Дальше/Сохранить), `test_tribun_owner` 34,
  `test_tribun_sport` 9, `test_tribun_sources` 21, `test_tribun_costs` 20, `test_tribun_legacy` 94 (все 79 прежних тестов SPORTBOT повторно с включёнными хуками + регрессии: шесть клубов, афиша не зависит от профилей, один планировщик, алерты без спама).
  **Мутационная проверка:** 46 намеренных поломок (роли, группа, агрегат, зависимости, «Другое», совместимость, health, coverage, cached/real, цены, cost guards, хуки) — все пойманы. Исправлено в тестовой оснастке: откат патчей в обратном порядке.

## 3. Состояние и данные (`/data`)

| Файл | Назначение |
|---|---|
| `today_matches.json` | состояние матчей v2: `matches{match_id: запись}`, `published_ids`, `meta` |
| `schedule.json` | известное расписание недели (ориентир для контроля изменений) |
| `admin_alerts.json` | какие уведомления уже отправлены (защита от спама, восстановление) |
| `last_morning.txt`, `last_weekly.txt` | дедупликация утра и афиши |
| `sport_meta.json` | последние фразы, версия последнего стартового уведомления |

| `tribun_sources.json` | здоровье источников по реальным запросам (раздел 2а) |
| `tribun_usage.json`, `tribun_pricing.json` | учёт API (агрегаты по дням, последние вызовы), цены и пороги, заданные владельцем |

Статусы матча: `found` (найден, анонс не отправлен) → `announced` → `awaiting_result` → `result_found`
(результат сохранён, не опубликован) → `published`; `expired` — результат не получен за 36 ч. Старый формат
(записи по ключу клуба) читается и переводится в v2; уже опубликованные результаты остаются `published`.
Запись состояния — атомарная; повреждённый файл сохраняется копией `*.corrupt-*`, а не затирается молча.

## 4. Конфигурация

Переменные окружения Amvera: `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, `DEEPSEEK_API_KEY`, `TAVILY_API_KEY`,
необязательно `OPENAI_API_KEY`, `DRY_RUN`, `FORCE_MODE` (`morning` / `results` / `weekly` / `test_openai`).
Адресат личных уведомлений: `ADMIN_USER_ID` (или `ADMIN_CHAT_ID`), иначе файл `admin_config.json` рядом
со скриптом (есть только в репозитории Amvera). Значения здесь не приводятся. Личные сообщения доходят,
только если владелец хотя бы раз открыл диалог с ботом (кнопка «Начать»).

## 6. Проверки

Автоматически: 335 тестов (раздел 2а); прежние SPORTBOT-тесты (`tests/test_sport_v4.py`, 79): первая проверка через 2 ч; публикация только после
подтверждённой отправки; сбой MAX → результат сохранён → повтор без нового поиска; перезапуск между
получением и отправкой; защита от дублей; миграция старого состояния (опубликованное не уходит повторно);
фразы football / hockey / universal; афиша (сортировка, «время уточняется», нет матчей, источник недоступен);
изменение времени / перенос / отмена; конфликт источников (другой счёт, «идёт» vs «завершён», календарь,
OpenAI), один источник недоступен, конфликт разрешился и не разрешился; один алерт и одно восстановление;
планировщик и `main`. Формат сообщений результата и анонса сверен с прежней версией (582 сравнения без расхождений);
мутационная проверка — 11 намеренных поломок тесты ловят. Разбор календарей проверен на реальных страницах
(урезанные слепки в `tests/fixtures/`).

## 7. Статус приёмки

Задеплоено в Amvera (`96d99db`). Live-приёмка по одному экрану приостановлена на время исправления каталога и продолжается: Футбол + Хоккей → Чемпионаты → Клубы → «Назад». Публичные тексты (описание группы, закреп, приглашение, зазывалка) автоматически не менялись; новые — после приёмки и утверждения.

## 8. Известные ограничения

- Amvera MCP был недоступен (504): логи сборки и запуска агенту не видны.
- Афиша и утренняя проверка зависят от вёрстки страниц sports.ru и superliga.rfs.ru; при изменении вёрстки
  бот сообщит один раз («не удалось получить расписание недели»).
- Часовой пояс страницы Синары принят екатеринбургским (по прежним записям бота); при расхождении возможно
  ложное «изменилось время» (сравниваются и часы на табло, и момент в UTC).
- Результат матчей с пенальти/сериями в мини-футболе сверяется по основному счёту.
- Автоматический поиск результата прекращается через 36 ч после начала матча.
- Старая версия не читает состояние v2 (см. откат).
- GitHub-репозиторий публичный; в истории остаются данные прежних версий.
- «➕ Другое» только собирает запросы: новых источников/парсеров/публикаций не создаёт; баскетбол и ВТБ — без источников (GAP).
- Цены на API не заданы (нет проверенного источника цен): стоимость в «💰 API / расходы» «неизвестна», пока владелец не введёт `/цена`; usage считается всегда.
- Текст приглашения (`INVITE_TEXT`) остался прежним и упоминает спортсменов/теннис/автоспорт — три актуальных публичных текста готовятся после live-приёмки.
- Каталог (`SEASONS`) — статический снимок 2026/27 от 2026-10-03; в течение сезона составы меняются (дозаявки, снятия) — при необходимости обновить снимок. Источники с `official=False` стоит перепроверить по сайтам лиг.
